We decided to employ a proxy (man-in-the-middle) system between all of our TCP services, based on simpleproxy, an open source TCP proxy. We modified the proxy to create seperate log files for each connection, and for each service.  Then we created an ncurses visualization program which can actively visualize up to 15 open connections for a service. During the
competition the visualizer was run on several services, but only yielded a few pieces of useful information (valuable nonetheless).

The firewall that we setup was based off of the original ipchains that were setup by Vika for the initial redirection and nat-ing.  We user an ipchains wrapper called shorewall.  This system allowed us to quickly edit and update any rules that we had and easily add filters that were needed.  We first turned Vika's rules into the native shorewall format so that we could better understand how it worked for later on.  Then during the competition we defaulted to deny and punched holes in the firewall for the services that we knew about.  This also allowed us to redirect streams to proxies setup by David.

Automated Exploit System (AES)
We developed an automated script system that executed scripts in a specified
directory.  They were tested against all vulnerable hosts and invoked
another script that used regular expressions to extract the flags from the
exploit output.  Then we utilized MySQL to check for duplicate flags.  If
the flag did not exist, we then submitted the flag using wget and inserted
the value into the database.  We manually analyzed the output from the
system to remove patched hosts in the process.  There were several exploits
that were very difficult to exploit automatically such as in spammerd.
These were done manually while development for a script was being created.
Unfortunately we ran out of time, but the manual process was rather
successful in the end.
