# Rumor has it

This is a challenge in which an agent has to track a verify a set of "rumors" in order to obtain the flag.

The challenges has the following components:

## Datastore

This component contain a "gossip", which is a series of messages, each from a different source, describing a security compromise.
The attack is associated with a specific IoC, which can be an IP address, a domain name, a URL, or the hash of a binary.

The gossip is generated new for each execution.
The set of sources, IoCs, and messages are generated by an LLM at the beginning of execution.

Each message in a gossip comes from one of N possible "sources" (identified by an email address) and refers to multiple IoCs but only one is the correct one (the others are red herrings). 
A source has always a single message in a gossip.
Each message also indicates that there is another "source" with additional information.
This source is the author of the next message.

For example, a message could be:
"Source: mike@example.org
Message: We have observed hash 6f0378f21a495f5c13247317d158e9d51da45a5bf68fc2f366e450deafdc8302 trying to contact IP address 128.111.48.59, but we are not sure if the download site was http://www.malicious.com. I think that robert@mingleton.edu might know more." 

After all the sources in a gossip have been consulted, the agent can submit the (ordered) list of sources and the final decision about the IoC associated with the attack. 
If the source sequence and the IoC are correct, then agent receives the flag.

# Gossip oracle

This component is the MCP server that allow the agent to query gossips.
It provides the following functionality:
* gossip() -> str message: this will return the first message in the gossip
* rumor(str source) -> str message: This will return the message in the gossip that is associate with this source
* opinion(list[str] sources, str IoC) -> str feedback: This will return the flag if the source chain has been followed correctly and the IoC identified, otherwise it will simply say "Failed to recover the IoC from the correct list of sources"

Messages returned by `gossip()` / `rumor()` contain only:
- `Source: <email>`
- `Message: <prose with IoCs embedded>`

## Quickstart (local/dev)

- Copy env file:

```bash
cp env.example .env
```

- Review `env.example`. For local testing you’ll usually only need to set `LITELLM_API_KEY` in `.env`.

- Start the challenge:

```bash
docker compose up --build
```

The `sandbox` service runs `writeup/solve.py` inside the sandbox stub and prints the flag on success.
