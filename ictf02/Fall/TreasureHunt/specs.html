Treasure Hunt Specs

This is a description of the treasure hunt exercise for the TAs, and the RSG students that may want to help in setting up the exercise.

Description

The two teams (Alpha and Omega) will compete in a treasure hunt. Each team will have to complete a number of tasks. The ultimate goal is to break into the security of a semi-realistic payroll system and perform banking transactions that will transfer money to an account of their choosing.

Network Topology and Setup

Each team will attack a separate network. It is important to keep the two team's traffic separate so that we obtain cleaner datasets.

The following describes one network target that will be attacked by one team. Two separate instances of this setup must be created.

The web server is placed on a DMZ network. The MySQL server (SQL host), the file server (NFS host), and the transaction server (TRN host) are placed on a separate network, accessible only by the web server host.

The web server is an Apache server, running as user apache. A number of broken CGI scripts allow one to view the source code of all the CGI scripts installed on the server. One CGI script is vulnerable to a phf-style attack. Another CGI script contains information about how to log into the MySQL database.

The file server exports the filesystem /home to everyone. In addition, it provides password files through NIS.

The MySQL server provides remote access to user dbuser with password bsecret. The server mounts /home from the fileserver. The team is supposed to modify the database so that the account associated with all the emlpoyees is actually one of their choosing.

The transaction server has a transaction account, whose encrypted password is included in the NIS password file. The password is banana. When connecting to port 7979, the user is dropped in a simple shell application. Typing HELP will show a list of commands one of which is PAYCHECK. The team is supposed to invoke that function to transfer all the employees paycheck to the attacker's account.

Detailed Configuration

The root password is "dyrwthm".

This network testbed requires:

  • Three Ethernet hubs and 12 Ethernet Cables
  • A PC (FWL) with 4 network cards and Linux RedHat 7.3 (server configuration). Tcpudmp logs will be collected at each of the 4 interfaces.
  • Two PCs (WEB_ALPHA and WEB_OMEGA) with Linux RedHat 7.3 (server configuration) and Apache, Snare, and MySQL client installed.
  • Two PCs (SQL_ALPHA and SQL_OMEGA) with Linux RedHat 7.3 (server configuration), and MySQL and Snare installed.
  • Two SparcStations (NFS_ALPHA and NFS_OMEGA) with Solaris 2.6 and the BSM audit system installed.
  • Two PCs (TRN_ALPHA and TRN_OMEGA) with Windows 2000 server and the Cygwin development environment.

Firewall host configuration

We assume that each interface is assigned with host address 1 of the respective subnet

The firewall host must be configured to enforce the following:

  • Perform NAT for hosts WEB_ALPHA and WEB_OMEGA
  • Route packets from eth0 to eth1 so that hosts WEB_ALPHA and WEB_OMEGA are visible from only CISL and GSL, respectively.
  • Route packets between WEB_ALPHA and eth2 and between WEB_OMEGA and eth3
  • A tcpdump process should be start on each interface. If possible, a script should be created so that if tcpdump processes die, they are automatically restarted

Web Server Configuration

  • Enable snare
  • WEB should be configured so that it accepts only traffic coming from one of the external network (CISL or GSL) and one of the internal networks (e.g., 192.168.20/24).
  • The Apache web server should be configured to run as user "apache" (the default). The doc directory should be /var/www/html. The CGI directory will be /var/www/cgi-bin. The apache account has been modified to have a valid login shell. The documents to be served are contained in the following archive. There are a number of CGI scripts to be installed on the web server. They can be find in this archive.
  • The home directory of the web server is chown-ed to apache:root
  • The password file on the web server should contain a normal /etc/passwd with a breakable user account password, namely leonardo:pizza.
  • Make sure that the web server does NOT mount /home/exports.
  • Make sure that a setuid version of grepshadow (with source) is in /tmp.
  • Make sure that mysql (the client) is installed.
  • Make sure that a directory called .ssh exists under /var/www with permission 700 and owned by apache.
  • The save_message.pl feedback script can be used to write to any file in the system (as user apache). Including other CGI scripts in the cgi-bin directory.
  • The checkperl.pl script can be used to read any file in the system
  • The query_extension.pl script contains a username and password for the database host.
  • The guestbook.pl script can be used to execute arbitrary commands

SQL Server Configuration

  • Enable snare
  • Install MySQL, create the dbuser user, and create the DB schema
  • Populate the DB schema with a number of users (include Dr. Christopher Schmidt)
  • Install and make setuid the timetracker program and the corresponding source, Both should go under /tmp.

NFS Server Configuration

  • Enable BSM
  • Configure the NIS system so that the following password file is distributed. The file contain a breakable password for user "transaction" (banana).
  • Configure NFS so that the file system /home is exported to the world
  • Modify SQL and TRN so that they mount /home from host NFS
  • Modify SQL and TRN so that they use host NFS as the NIS server

Transaction Server Configuration

  • Install Windows 2000 server and Cygwin
  • Enable event logging
  • Configure ssh
  • Install transaction.c and transaction.pl
  • Run transaction.exe 7979 and logout (you will have to do a ESC-RET-RET-TILDE-DOT)

Tasks

In the following, the different tasks that are part of the treasure hunt are described, in the order in which they will be presented to the two teams.

For each tasks the section Assignment specifies the information that will be given to the team. Every other information is for the organizers only.

Task 1: Network scanning

Assignment

Determine the active hosts in subnet 128.111.48/24. Determine also the hosts OSs, and the services/applications that are remotely accessible. Scanning techniques that will evade detection by the Snort system will receive additional bonus points. You have 20 minutes to complete this task.

Cheat Sheet

The firewall will drop scan packets causing long delays in portscans. Use a "horizontal" approach were you first try to ping all the hosts (maybe using TCP) and then focus only on the hosts that respond to the query.

Solution Sheet

The host is a PC with Linux RedHat 7.3 that is the web server of the Bass Tard Corporation.
