Mission:       The mission of the group was to attack the hosts that are found to be alive by the IP mapping Group and to target the attack only to those ports that are found to be open on those machines.

                      The aim of the attack is to gather extra information about the open ports and the daemons running on them, such as the version of sshd running on port 22, the web server running on port 80, and, if possible, the website which it is hosting.

                       We were to attack/defend/detect the attacks. We were also to detect the IP Frag attack launched against us to scan the ports open on our machines.

Preparation:

We used NMAP to do that. We obtained the version scanning NMAP  tool which was developed by Jay (another member of the Alpha team), that does version scanning.

 Attack:

We were to find out a stealthier way of doing that. We started looking at SNORT and NMAP options. We did a few things:

             (1) We found that if we distribute our scans over a long period of time, they are less detectable. Therefore, we used the --scan_delay option of NMAP.

              (2) We found that in Snort, the default value of MAX_DEFAULT_PORTS is 20, so we did our version scanning by scanning 5 ports per run. We used the -p option to specify the ports, and we used only those ports that were found to be open by the Port  mapping group.

             (3) Since we already know which ports are open and since we only try to attack those ports, we used -sT, which is the best option for version scanning in terms of traffic/speed.

              (4) To make our attack stealthier, we used NMAP's version  scanning with the -sV option, which tries to do scanning with as little traffic as possible. If we don't find any information, we try -sVV and then -sVVV.

              (5) We had written automated scripts/programs that read the open ports from a file and performed the stealthier version scan on those ports and on each alive machine, storing the results in a file.

                (6) We passed the gathered information to the OS FingerPrinting Group, if it helps, (in some cases, it does), to get the OS of the target machine.

 Defense/Detection:

             (1) We modified Snort's default variable for the number of target ports by setting it to 5, so that even an attack with few ports in each attack run can be detected.

             (2) We added a rule in SNORT that generates an alert each time an ICMP Fragmentation Time Exceeded is sent back, i.e. considering it as a probable attack.

             (3) If the other team is using the same version of NMAP that does version scanning, their host's IP can be easily caught because the decoy option is not supported in NMAP.

              (4) There is not much we could do to stop the other team from doing version scanning, and most of it can be detected by analysing the tcpdump files.

Evaluation:

                (1) We were able to gather information on the hosts and about all the daemons running on the open ports. We were also able to gather some OS Fingerprinting information from the results.

                (2) We were also able to detect portscans on our machines. As we changed the MAX_DEFAULT_PORTS to 5 from 20, we detected more port scans.

                (3) We tried to be detected as less as possible, i.e. we tried to do it stealthily and we tried to generate as less traffic as possible.

Miscellaneous:

We planned to use NMAP's spoofing options while doing version scanning, but the decoy option of nmap+version does not work with the decoy option. Furthermore, we thought of doing a run of scans, changing the IP address of the machine from which the attack is being launched. However, as we usually have very few ports open on a machine, we determined that it won't be effective. Moreover, we didn't want any disruption by doing this on the only machine over which we have full control.
