Mission

IP Mapping's mission involved three things:

Host discovery - IP Mapping had the task of identifying which hosts existed on the oponnent's network. This task needed to be completed accurately and extremely quickly in order for other members of our team to proceed.

Detection - IP Mapping was responsible for detecting when the oponnent attempted to discover our hosts.

Prevention - IP Mapping attempted to prevent the oponnents from discovering our hosts. We attempted to emulate hosts on the entirety of our network, making it impossible for automated techniques to identify our real hosts.

Preparation

Preperation falls into three categories:

Host discovery - Several custom tools were developed to perform host discovery. An ICMP timestamp sweep tool was developed by Dave Fayram. This performed a sweep of a destination network with ICMP timestamp requests. It also used these packets to check latency on the target hosts and perform very primitive OS fingerprinting. A UDP sweep tool was also developed by Dave Fayram. This tool swept the target network with UDP packets to a closed port and watched for ICMP port unreachable messages. It also performed very primitive OS fingerprinting (useful when passing on host information to the OS fingerprinting group). Finally, an IP fragmentation sweep tool was developed by Dave Fayram which was ultimately not used. It sent out one fragment of a fragmented packet and waited for an ICMP Fragmentation time exceeded response. Due to poor communication, Subhra also developed an ICMP timestamp sweep utility, which, while it worked, was ultimately not used.

Detection - Both Snort and netstat were prepared for IP Mapping detection. Netstat scenarios were developed to detect various sweep attempts, and snort rules were developed to detect slow sweeps.

Prevention - Several tools were developed to emulate hosts and make locating our real hosts extremely difficult. The biggest part of our prevention involved the extension of the software package LaBrea by Bryan Cassell to accurately emulate hosts. The software was heavily extended into three different branches - a linux 2.4 branch, a linux 2.2 branch, and a windows 2000 branch. Each of these branches emulated the respective host type very accurately with regards to TCP and ICMP traffic. Two other tools were developed which were ultimately not used due to minor bugs that couldn't be fixed in time for the exercise. The first was a UDP emulation tool developed by Gilad Benjamin that would send out ICMP port unreachable messages when a udp packet was sent to a "closed" port on an emulated host. The second was an IP fragmentation emulation tool developed by Ryan Bane that would send an ICMP Fragmentation time exceeded packet back to a host if all fragments of a fragmented packet were not sent.

In addition, 2 laptops were prepared by Dave Fayram and Bryan Cassell to launch attacks and detect traffic from. These machines were prepared in such a way (using firewall rules and disabling ARP) that they would be invisible on the network while still being able to send spoofed packets and watch the network in promiscuous mode.

Evaluation

Overall our team performed very well:

Host Discovery Host discovery went incredibly well. We were able to find their hosts immediately. We only had one mis-identification of a real host, which was quickly remedied. We were also able to find the hosts on the external network immediately. We were able to pass this information on to the other teams right away, and our rough OS detection was a great help to the OS fingerprinting group.

Detection As of the writing of this report, our detection is still under evaluation.

Prevention Our tool for host emulation worked exceptionally well. For half an hour, the other team could not determine what hosts on our network were real. Unfortunately, about 30 minutes into the exercise, alpha, the machine that was running our host emulation software, froze and had to be restarted. For about a minute and a half alpha was down, and the only hosts responding on our network were the three real hosts. In that time, the omega team scanned our network, saw only three hosts, and determined those were the real hosts. It is unclear how long our prevention techniques would have worked, but judging by our success in the first 30 minutes, it is VERY dissapointing that alpha crashed. The fake hosts were brought back up as soon as possible, but it was too late to stop omega team from discovering our hosts while alpha was down. This was definitely the greatest dissapointment for the IP mapping group.

Overall the IP Mapping group performed very well. All of our tools were very effective, and there isn't much we could have done better. If alpha hadn't crashed, our setup might have been near perfect.

As for suggestions for the exercise itself, some people feel that there should have been more numerous or more varies hosts. Also, the exercise itself was somewhat disorganized, which is somewhat understandable considering the complexity, though it would have been nice to have more of a reserved area in CSIL.
