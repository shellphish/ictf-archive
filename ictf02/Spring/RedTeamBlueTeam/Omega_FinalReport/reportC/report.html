Preparation

Tools developed:

    - Test4.cpp - which contains a function find(). The function search the flag file from the specified root, and return the absolute path of the flag file.

    - Hcycle.sh, debugfs - debugfs is a tool to investigate and modify the file system manually. Hcycle.sh is a bash script developed by us to call debugfs easily. We use them to create cycle consisting of hard links.

    - Cdir.sh - it is a bash script developed by us to create a big deep directory tree.

Methods used:

Hiding the flag file

    - Putting the flag file in a big tree

    - Creating the cycle using symbol links

    - Creating the cycle by modifying file system directly. (We use debugfs to create hard link for a directory entry to its parent directory.)

    - Creating many false secret.txt to decoy the attacker

    - Creating symbol link ?secret.txt? which points to a file containing the correct contents to decoy the attacker.

Searching the flag file

    - Traveling the entire file system

    - Ignore all symbol links to avoid the cycle

    - Remembering all <inode#, dev#> handled by our search function to avoid the cycle consisting of hard links.

    - Using relative path instead of absolute path to avoid exceeding the file system limits.

Evaluation

The tricks used to hide our flag file are quite successful. The attacker's search program decoyed by one trick, which create a symbol link named 'secret.txt', and point it to a file '_secret.txt' containing the correct contents.

But our search function didn't find the flag file on the target machine within the required time span.

Later, we discuss our search function. The conclusions are that:

    - A multithread program is better than a single-threaded program

    - To select the candidate directory is better than search them in the alphabetic order.
