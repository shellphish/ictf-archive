Blue Team Report

 

·       Team/Subgroup

 

Group Name:            Blue Team / Network Subgroup

 

Description of team activity: The Network team is responsible for monitoring the network traffic during the war and producing meaningful reports.

 

Team Members, email and handles:            Sankaridurg Sivaguru (srsiva@cs.ucsb.edu, borntohack), Ashwani Wason (ashwas@engineering.ucsb.edu, ashes), Rune Satre (satre@cs.ucsb.edu, rs), Ahmet Bulut (bulut@cs.ucsb.edu, bulut007)

 

Group Leader: Ashwani Wason.

 

·       Mission

 

Team responsibilities: The Network team is responsible for monitoring the network traffic, during the war. The team will log all attacks that were sensed and produce reports that try to reconstruct the sequence of steps made by the red team. The network team will only log the attacks as they are sensed and will NOT do anything to filter traffic when such attacks are detected.

 

Responsibilities of each group member:

 

Ashwani: Detecting portscans using snort rules; Detecting access to file secret.txt in incoming ftp, mail and outgoing ftp, telnet and mail packets using snort rules.Using Netstat IDS to write rules to do pattern matching on packet streams.Writing a program for detecting IP spoofing.

 

Siva: Writing snort rules for detecting pingscans. Using the tcpStream preprocessor in snort to write rules to detect file access to secret.txt in input telnet stream. Using identd to detect breach of trust relationships.

 

Rune: Writing perl script to generate snort rules to detect used and unused service access. Detecting IP spoofing during the exercise. Looking for snort signatures for the latest attacks. I was contacted by members of the red team and bribed into sending them the secret file from the NT machine. Since the NT machine is not part of the game, I decided to send them a fake file. Just to keep them thrilled.

 

·       Preparation

 

Planned activities:            Using tools and writing programs to:

Detect ping scans, Detect portscans, Detect IP-spoofing, Detect access to secret.txt in incoming and outgoing packet streams, Detect violation of trust relationships, Write scripts to create rules to detect use of used and unused services during the exercise, and Search and install latest signatures that address a number of attacks

 

Tools, methods and software: The following tools, software and methods were adopted to achieve the above mentioned goals. The author of each of the detection methods listed below is mentioned inline.

 

·         Snort: Snort rules were written to detect access to used and unused services, detect latest attacks, and access to secret.txt in “multi-byte” tcp and udp streams.

·         Tcpdump: Tcpdump filter was written to detect Ping Scan by checking the number of ARP Requests generated by the router within a short span.
Libpcap: Libpcap was used to write a tool to detect IP-spoofing by using domain specific knowledge about testbed network. Ashwani Wason developed this tool.

·         Tcpd, identd: Tcpd and identd services were investigated for their uses in detecting breach of trust relationships.

·         Perl: Perl scripts were used to automatically create rule sets for activity 6. Rune Satre implemented the perl scripts.

·         Netstat IDS: Netstat IDS was used to do pattern matching on packet streams.

·         TcpStream Preprocessor: Stream pre-processor was used to detect potential access to secret.txt in incoming “byte-at-a-time” tcp streams.

·         PortScan PreProcessor: The portscan pre-processor was used to detect UDP and TCP portscans

 

 

·       Execution

 

Siva and Ashwani were watching pingscans, portscans, file accesses and monitored network traffic to provide early warnings to host teams.

Rune and Bulut were detecting IP-spoofing attacks, access to used and unused services and looking through the snort logs to find attack patterns.

·       Evaluation

 

Our team was able to monitor and detect a lot of attacks. The warnings that we gave to the host teams, helped them prepare for the attack and gave them good directions about what to look for in their host. The responsibilities in the network team were well distributed and organized, and this ensured that the logs collected were not overlapping and redundant. The logs produced by Netstat were most helpful in re-constructing the sequence of steps made by the red-team to accomplish the attack. Other tools could only provide us with pieces of information that were not very helpful in the re-constructing the attack. The log files that were collected were complete and provided a great source for the post-mortem analysis.

 

·       Miscellaneous

·        The activities of the exercise should be organized better to promote interaction between subgroups of a team.

·        The blue team should be given a chance to prevent these attacks as the case would be in real life.

·        Red/Blue exercise should be one week earlier, to leave more room for final project testing.

·        The IP-addresses of the hosts that we were protecting were changed just before the war without sufficient notice for us to change our programs and rules.
