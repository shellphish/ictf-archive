2). Task

Intrusion detection for host: altman (128.111.54.157).
 

2. Mission


Host based intrusion detection. Our mission is to hide the flag and detect red team attempt to capture the flag. Due to the time limits
and the blue/red team rules, we are concentrating on adapting existing tools to detect. Our system is multiple-level detection: Network
level, Host Entry level and On-host Activity level.

The task is done as a group. Instead of assigning individual to each subtask, our group works together in each stage.
 

3. Preparation


1) Network Level:

For protection of our host from network level intrusion such as topology mapping and port scan, we modified the "snort". It fakes
non-existing hosts by using spoofed arp reply and icmp reply, and provides non-existing services by using man-in-the-middle style TCP/UDP  redirection.

We use modified "snort" framework to log for further investigation. In  addition, we installed the "ethereal" to interactively monitor the
live flow on the net.

2) Host Entry

We implemented in two ways. First, monitor any new established TCP connection. Second, monitor any new "/bin/sh" process. The second one targets "buffer overflow" attacks. They are all done in Perl scripts through "lsof" and "ps".

3) On-host Activity

By using "strace", we monitor any suspicious process activity. Two scripts are written for monitoring sshd and telnetd. Here we want to
emphasis that secured shell is not "secured" for host. It is just secured in transmit, but it is "clear-text" for host.

5. Evaluation

1) Evaluation

Our subgroup is fairly good, especially our customized "snort" which has generated a lot of decoy and achieved its object. Although it would be even better if we have time to add in icmp redirect to defeat all OS fingerprint attacks.

Our host defense is kind of weak since we are highly limited by the rules.  Our scripts automatically detect possible attacks and start logging on them. Based one those logging, we can reconstruct the attacks. But it could be better if our detection can pick out the real attack from other false alarms. Another important lesson will be that the defender should not trust anything when the host is compromised.
 

2) Suggestion

The subgroup interaction in BLUE team is very limited. If it is organized by task as RED team has done,  instead of by host, our defense will much stronger.  It will allow subgroup to concentrate on one area(task) and the result can be shared by all hosts.
