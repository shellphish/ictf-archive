Mission

Our final goal is to protect the secret flags from illegal access and to record all malicious behaviors on our local host. To achieve this goal, we mainly focus on the following tasks:

n      Building “confusing” file structures to protect secret information (Zhou and Wen)

n      Building control environment to reduce malicious attack and enhance monitoring, including honey pots setups. (Cai, Su and Lu)

n      Detecting malicious attacks.

A. file monitoring (Wen, Zhou)

B. process monitor (Wen, Zhou and Cai)

C. network monitor (Su and Lu)

D. user monitor (Su and Lu)

 

Preparation

We have done the following planning prior to the exercise. Responsibilities are listed within the parentheses:

n      Information hiding

In order to achieve information hiding, we have planned the following:

1.        Designing multilevel file hierarchy (Zhou and Wen)

We designed a file structure to prevent non-authorized users to find the secret flag easily. This is done by building extremely deep hierarchical directory structure with long file names. The effect of such operations causes errors in executions of common utilities, such as grep/egrep/find. This method effectively prevents intruder from gaining access of critical information. The building process is done by a specially designed C program “gentree”. 

2.        Allowing legitimate super-user from retrieving critical information (Zhou)

Special C program “puttarget”is written to allow legitimate users to perform find operation to the critical information.

 

n      Intrusion detection

We have installed the following intrusion detection tools to monitor the host activities: (Lu)

n       Hunt

n       Log-Check

n       Port-Sentry

n      Snort

 

Normal users are placed in a more controlled environment for monitoring purposes. We have automatically built special bin directory for each user. Appropriate versions of UNIX commands (some of these commands are modified or replaced by shell scripts) are placed in these bin directories. These commands “somehow fail” when a user is attempting to access secret information via these commands. The automated building process is handled by a shell script called mkddd.

 

Shell scripts/programs are written to replace the common UNIX process/file related commands to help recording user activities. The following commands are modified: (Su)

n       Ps

Root processes are not displayed for non-guard users. The login of the user is recorded in a log file. 

n       Which

Rather than displaying the location of the user commands, it displays the location of the supposed normal UNIX command.

n       W

For non-guard users, sensitive information is not displayed. The login of such user is recorded in a log file.

n       Lsof

For guard users, lsof directly calls the corresponding UNIX commands. For nonguard users, the login of the users will be kept in a log files. Sensitive system files are not displayed.

n       Top

Keep track of non-guard users which access this command in a log file.

 

New program/scripts are written to report suspicious user processes. Unusual file accesses are recorded. We have the following scripts/program:

n       Chkps (Wen)

Match suspicious commands/open files appeared in non-guard user processes. Detail reports are recorded in log files as well as displaying in blue team terminals.

n       Guard (Su and Cai)

      Check all files opened by users, pay special attention to sensitive system files opened by non-guard users, storing such information in a specified log file. Continuos display unusual events for monitoring.

n       PIDS (Wen and Zhou)

A comprehensive IDS detection system designed by ourselves (which is also the project for this course) is employed to handle the tasks such as port scan, arp spoofing, log checking, and user monitor

 

Execution

During the exercise, we mainly focus on monitoring the following aspects:

a)     File monitor

Started PIDS; (Wen)

Started LogCheck; (Zhou)

Periodically using scripts (chkps and lsof) to check the open file access. (Wen and Zhou)

Periodically checking the PIDS log file to check the access to sensitive system files, such as /etc/passwd and some commands (grep, find, etc.) (Wen and Zhou)

b)     Process monitor

Periodically using chkps to scan the process lists to check the suspicious process. (Wen)

c)      Network monitor

Started HUNT; (Su)

Periodically check HUNT for telnet connection and watching some connections; (Su and Cai)

Periodically executing NetStat to monitor the network connections to check vulnerable services; (Su and Cai)

Detect various port scans using “PIDS”/Snort. (Ping scan / UDP scan / TCP SYN scan /TCP FIN scan, etc). (Lu)

d)     User monitor

“PIDS’ are used interactively to monitor non-guard users. Logs are created upon non-guard user logins. Operators (Su and Lu) report suspicious behaviors.

 

Evaluation

The main goal of protecting the secret flag is accomplished (with the regret that our host is down for certain amount of time). Illegal operations by red team are recorded during the exercises. Our team members are aware of certain attacks to our host. However, root control is lost during the end of the war. 

n      Successful detection

Various Port scans are detected even during the early phase of the exercise.
